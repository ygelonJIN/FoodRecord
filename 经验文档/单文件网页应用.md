# 单文件网页应用

**什么时候读**：改这个 app 的数据结构、计算规则、界面样式、浏览器自动化验证之前；或者给别的项目做同类「一个 HTML 本地工具、数据存浏览器」的东西时。

---

## 项目结构与数据契约 —— 改数据模型之前看这节

### 文件就一个

`index.html` 里依次是 CSS、页面骨架、JS。JS 内部按注释分成：数据层 / 计算层 / 渲染层 / Sheet 交互 / 导入导出 / 事件 / init。
加功能就往对应区块塞，不要为了"结构清晰"拆文件、引框架、上构建。手机上靠一个静态服务器就能跑，拆了就多一层麻烦。

### state 形状（v2 起是「多配置」）

存储键 `foodrecord.v2`，形状：

```
{ v:2, active:<配置id>, legacyBackupSaved?:true,
  configs:[ { id, name, profile:{weight,carbX,proX,fatX,sugarX},
              foods:[{id,name,unit,p,c,f,s,kcal}],
              logs:{ 'YYYY-MM-DD': {breakfast:[],lunch:[],dinner:[],snack:[]} } } ] }
```

- 运行时的 `state` **就是** `store.configs` 里的当前配置对象（同一个引用），所以老代码里直接改 `state.foods` / `state.logs` 不用回写；只有换配置、整体替换时才动 `store`
- 每个配置独立拥有食物库、每日目标和记录；统计、今日页都读 `state`，天然跟着切
- `foods` 的**数组顺序就是用户自定义排序**，别在渲染时再 sort；`食品库` 和添加面板共用这个顺序
- 旧版 `foodrecord.v1` 是单配置结构，只在迁移时读一次

- `foods` 里存的是**每 1 个单位**的营养值，`unit` 是给人看的（`1个` / `1份` / `3块`）
- `foods[].kcal` 是**可选**的实测热量，`null` 表示按宏量公式算
- `logs` 的条目存**营养快照**（name/unit/p/c/f/s/kcal + qty + foodId），不是纯引用

### 三条不能破的规矩

1. **条目存快照，但改食物要同步进历史记录**。条目各自存一份营养值，算数一律用快照、不回食物库反查；区别是编辑食物时 `syncFoodToLogs()` 会把名称/单位/四项营养/热量写进所有 `foodId` 相同的条目，**份数不动**。删食物不动历史（条目留着旧快照），`foodId` 为空的老条目也不动。
2. **每次读 state 都要容忍缺字段**。`normalize()` 负责补默认值，从 localStorage 反序列化出来的东西先过它。
3. **改存储键要带版本**。v1（单配置）→ v2（多配置）就是这样升上来的：先读 v2，读不到再拿 v1 迁成一个叫 `jfq` 的配置，迁完立刻同步写 v2，旧的 v1 等用户存完备份（或明确不要）再删。下次再改结构就升 v3，别原地改字段名——用户手里的数据是活的。
4. **换配置只走 `enterConfig(cfg对象)`**，它统一处理 `store.active`、`state`、日期归位和整页重绘。直接 `state = xxx` 会漏掉重绘和落盘；传 id 字符串进去会在 `renderLibrary` 崩（这个坑真踩过）。

### 一个必须做的动作

init 里第一件事就是 `save()`。种子数据不落盘的话，每次刷新都会重新生成一遍食物 id，记录里的 `foodId` 就跟食物库对不上了。

## 计算规则 —— 动数字之前看这节

- 热量有两条路：食物填了 `kcal` 就用填的，没填才按 `蛋白 4 / 碳水 4 / 脂肪 9` 换算
- 取热量的唯一入口是 `unitKcal()` 和 `entryKcal()`，不要在别处再写一遍乘加，否则手填值会被绕过
- **糖是碳水的一部分**，只单独统计，绝不重复计入热量
- 目标 = 体重 × 倍数，默认碳水 3 / 蛋白 2.5 / 脂肪 1 / 糖上限 0.5（g/kg）
- 目标热量由三宏量倒算得出，不单独设一个 kcal 目标，免得两边对不上
- 进度条超目标标红，宽度封顶 100%；总量超了顶部大数字也标红

改完一定回归一次：录入几条 → 拿 localStorage 里的原始数据独立重算 → 和界面上显示的数字对比。只靠眼睛看会把 4/4/9 记混。

回归时必须覆盖两种食物：一个填了 `kcal`、一个留空。只看留空的测不出手填分支有没有断。

## 样式约定 —— 做界面之前看这节

### 苹果原生的观感怎么来的

- 全部颜色走 CSS 变量，暗色模式在 `prefers-color-scheme: dark` 里覆盖同一组变量，不要在组件里写死颜色
- 分组卡片：白底、16px 圆角、`0.5px` 描边（用 `box-shadow: 0 0 0 .5px`，比 border 干净）、卡片间距 10px
- 正文 17px，标题 32–44px 带负字距，副信息 12–13px 走 `--label2`
- 三级灰：`--label`（黑）/ `--label2`（.60 正文辅助）/ `--label-mid`（.76 目标值、输入值）/ `--label3`（.30 次要、热量）。目标数字用 mid，不要用 label3——看不清楚
- 数字全部 `font-variant-numeric: tabular-nums`，滚动时不会抖
- 顶部导航和底部标签栏都加 `backdrop-filter: blur(20px)` + 半透明底
- 固定栏和底部弹层必须带 `env(safe-area-inset-*)`，不然会撞刘海和 Home 条

### 纯文字界面（用户硬要求）

用户明确要求：**界面上不要出现任何图标**，也不要一键截屏之类的花活，界面本身就是用来直接截屏的。

- 不用 SVG、不用 emoji、不用图标字体；餐次就叫「早餐」，不要 🌅
- 标签栏、日期翻页、列表行尾全部用文字，不用箭头符号和 chevron
- 唯一保留的装饰是宏量色标圆点，那是数据可视化，不是图标
- 另一个明确的例外：食物库每行最左侧的拖动灰条（用户要求「拖动条要有样式」），它只能是一条纯色竖条，不要换成点阵、三横线或箭头
- 想加图标之前先问自己：这行字是不是已经说清楚了？说了就别加

### 首页顶部的信息层级

用户要的主次是「碳水 蛋白质 脂肪 糖 > 热量」。热量是推导出来的副产品，不是主角。

- 总量的外框和餐卡完全同构：先用一条 `meal-head` 写「总量」，下面才是五行
- 五行横排，一行一项：标签（44px 定宽）→ 进度条（flex）→ `当前 / 目标 单位`
- **进度条一律蓝色**，不要按营养分别上色，更不要超标换色——彩色堆起来太花
- 超标只把当前数字变红，条保持蓝色满格，红色就是唯一的警示信号
- 当前值 15px 加粗黑，目标值用 `--label-mid` + 600（不能太灰，也不能抢主数字）
- **不写「蛋白还差 X g」这类推导提示**，用户已明确不要

不要做成三列大格子：竖排格子会把热量顶成视觉中心，而且三列放不下糖。

### 餐卡的信息层级

一餐两行结构，左右分工：

- 餐头：`＋`（左，30px 蓝加号，点它加食物）→ 餐名（flex）→ 右侧五连数字 `碳水30 蛋白质15 脂肪12 糖5 288`，全部用 `--label` 黑色
- 条目：`份数×` 在最前面（黑色 600）→ 食物名（flex，长名允许折行）→ 右侧同样五连数字，全部用 `--label2` 灰色
- 黑色 vs 灰色就是「合计」和「明细」的层级差，不要再靠字号区分
- 热量放在五连数字的最后一格，前面多 3px 间距，字重比前四项轻一档
- **四项营养写全称，单位 `g` / `kcal` 也全写**。全称加单位一行约 200px，所以数值压到 10–10.5px、gap 4–5px、单位用 9px 的 `<em>` 挂上去
- 单位 `color:inherit`，跟着数字走：餐头黑色数字配黑单位，明细灰色配灰单位。别给单位单独设一个更淡的颜色——用户要的是「300g」读成一整个值
- 窄屏下的取舍已经定死：数值不许省字，宁可让长食物名折行。普通名字（4–6 字）刚好一行，超长的折两行

餐头底部有 `.meal-head::after` 画一条分隔线，和条目之间的 `::before` 保持视觉连续。

空餐就只留 `＋ 餐名`，右侧不渲染任何 0，卡片自然变矮。

### 食物库拖动排序

- 交互定死：**每行最左侧 32px 是拖动条，按住就直接拖，不用长按**；行里其余位置单击仍然是编辑，上下滑仍然是滚页面。不要加「排序模式」按钮，用户要的是直接拖
- 也不要整行直接拖：手机上想滚页面会变成起拖，所以拖动只认最左那条；代价是行内文字头一个字会被拖动区压住一半，点到那里照样是编辑
- 拖动条是 `.librow .grip`：绝对定位、`touch-action:none`，只占原有左边距、不改文字位置；那条 4×20px 的灰色竖条（`::after`，颜色 `--label3`，按下变深变长）就是它，用户明确要求这里有可见样式，别当成图标删掉
- `pointerdown` 用 `closest('.grip')` 判断，别的区域直接返回；拖动区宽 32px，会压住食物名第一个字的一半，点到那里照样编辑
- 实现是「隐形占位 + fixed 克隆」：原行加 `.ph` 只留位置，`body` 里挂一个 `.librow.ghost` 跟着手指走，每次 `pointermove` 只做 `insertBefore`，松手按 DOM 的 `data-id` 顺序回写 `state.foods`
- **监听必须挂 `document`，pointer capture 必须挂 `body`**：行在拖动中会被 `insertBefore` 搬走，Chrome 会因此释放挂在行上的 capture，之后 `pointermove` 越来越少、`pointerup` 直接收不到——表现就是「拖一点就卡住、松手也放不下来」，浮层永远挂在屏幕上（实测 24 次移动只收到 9 次）。挂在 document 上、capture 到 body 就与行的搬动无关了
- 起拖门槛是位移超过 4px，轻点不会闪一个浮层；拖动中分别在 `pointermove` 和 `touchmove` 上 `preventDefault`（iOS Safari 只认 touchmove）
- 插入点按**浮层中心**越过行中线算，不按指针位置：按指针算，到顶和到底会来回跳
- **必须带边缘自动滚动**：指针进视口上下 72px 就按距离滚（每帧最多 20px），每帧重算插入点。少了这个，长列表里只能拖到「当前屏幕第一条」上面，永远到不了真正的第一条（这个 bug 踩过）
- `pointerdown` 统一挂在 `document` 上，行是动态渲染的；行要 `user-select:none` + `-webkit-touch-callout:none`，不然 iOS 长按弹选择菜单
- 拖完必须设一个 ~400ms 的 `libClickGuard`，否则手指抬起后的 `click` 会把编辑面板顺带打开
- 搜索有过滤时直接禁用拖动，否则「过滤后的顺序」和完整数组对不上

### 空态不要写占位文案

没有记录的餐次直接只留「餐名 + 添加食物」，不要显示"还没有记录"这种话。四餐空着的时候，屏幕上就是四个干净的入口，比四行灰字好看，也更适合截图。

### 统计的口径

- 三个窗口都是**滚动的近 N 天**，不是日历周月年。日历周期在周一早上只剩 1 天数据，会误导
- **窗口一律截止到昨天，不含今天**。今天还没过完，把它算进平均会把均值拉低；`daysAgo(1)` 是固定终点
- 均值一律**按有记录的天数算**，不能让没记的日子把均值拉低；界面上写清「N 天中 M 天有记录」
- 每段必须写起止日期，跨年要带年份
- 历史列表默认出 30 条，剩下的用「再看 30 天」翻，避免积累一年后滚动几千行

### 三个 CSS 坑

1. **`<button>` 默认是 shrink-to-fit**。整行按钮（比如"添加食物"）不写 `width:100%`，边框只画文字那一截、文字也不居中。样式里第一件事先给 `width:100%`。
2. **`.view` 切换用 `display:none`**，不做动画卸载；`position:fixed` 的弹层独立于页面流，别塞进 `.view` 里面。
3. **弹层键盘遮挡**：用 `visualViewport` 的 resize 算出键盘高度写进 `--kb`，弹层的 `padding-bottom` 读它。
4. **改完 CSS 必须读 computed style 复核**。字符串替换差一个 `;margin-left:3px` 就会静默不生效，而脚本里的 `assert s != orig` 因为别的改动照样通过——测出来界面没变，才知道替换落空。

## 浏览器自动化验证 —— 跑测试之前看这节

### puppeteer 已经连不上了，改用 chrome `--dump-dom`

本机 Chrome 156 配 puppeteer-core 24.43.1，`launch()` 之后任何 `page.goto()` 都报
`Requesting main frame too early`，`headless: true/'new'`、`pipe: true`、加各种 args 都不救。
不要再在这上面耗时间，直接走命令行：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --no-sandbox --window-size=520,900 \
  --user-data-dir=/tmp/prof --dump-dom --virtual-time-budget=10000 URL
```

配一个 python 静态服务器（`python3 -m http.server`）提供页面，别用 `file://`，localStorage 要真源。

### 断言脚本直接注进页面，结果塞 title

把 `index.html` 读出来，在 `</body>` 前注一段 `<script>`，断言写在这段里。app 的脚本是普通
`<script>`，`state` / `renderAll` / `sheetFoodForm` 这些顶层 `let`、`const`、`function` 都在全局词法作用域里，
后注入的脚本能直接按名字拿到、直接调用，不用绕 UI 点击。

- 结果用 `document.title = 'RESULT:' + encodeURIComponent(JSON.stringify(arr))`，从 dump 出来的 HTML 里正则抓 `<title>` 再解码
- 用 `--virtual-time-budget` 把 `save()` 的 60ms 防抖跑完，再在结尾 `setTimeout(…,300)` 里读 localStorage 核对落盘
- "刷新页面验证持久化" 用同一份 `--user-data-dir` 跑两次：第一次写、第二次只读，等于换了页面没换存储
- 要预置数据就别 reload：先 `localStorage.setItem` 再 `state = loadState()`，顺带把反序列化也测了

BSD 的 `sed` 处理 title 里的转义括号会报 `parentheses not balanced`，抽取一律用 python。

### 自动滚动要先把 rAF 换掉

`--dump-dom` 下页面只跑一帧 `requestAnimationFrame`，靠 rAF 驱动的自动滚动在测试里完全不动，看起来像没生效。
测拖到顶之前先把它换成 `setTimeout(…,16)` 的 shim（`window.requestAnimationFrame = cb => setTimeout(() => cb(Date.now()), 16)`），
再等够虚拟时间；真实浏览器里 rAF 是正常的，别因为这个改掉实现。

### 合成指针事件测不出 capture

注入脚本里 `dispatchEvent(new PointerEvent(...))` 不会建立 pointer capture，所以「行被搬走后丢 capture」这类 bug 永远测不出来（漏过一次：拖一点就卡住、松手也放不下来）。
要测真实指针就走 CDP：headless 加 `--remote-debugging-port`，从 `/json/list` 拿 ws 地址，依次发 `Input.dispatchMouseEvent` 的 `mousePressed` / 多段 `mouseMoved`（`buttons:1`）/ `mouseReleased`，再用 `Runtime.evaluate` 读 `state.foods` 和浮层数量。同时分别数 document 上的 `pointermove` 和行里监听收到的次数，两者不一致就是丢了。

### 点击只调函数，不点坐标

固定的标签栏会盖住元素，按坐标点一会儿成功一会儿超时。统一在页面里触发：
面板直接开（`sheetPickFood('dinner')`、`sheetFoodForm(id)`、`sheetQty(null, entryId)`），
要提交就 `document.querySelector('[data-sheet="saveFood"]').click()` —— 事件委托照样跑，绕不过去。

### 界面操作和断言同步跑

`openSheet()`、`renderToday()`、`saveFoodForm()` 全是同步的，`innerHTML` 直接换掉，注入脚本里一路同步调下去就行，
只有 `save()` 的 60ms 防抖要等。别在里面加 `await wait()` 那种东西，命令行模式下拿不到。

### 截图会骗人的几处

1. headless 的窗口有最小宽度（约 500），`--window-size=390,844` 截出来是**右边被切掉**的 390 宽图，不是布局坏了。**判断有没有溢出量 `scrollWidth`**，要看完整布局就用 520 宽截。
2. 单页截图不会重复 `position:fixed` 元素，这一点命令行模式比 puppeteer 干净。
3. 弹层有 `.34s` 的 transform 过渡，`--virtual-time-budget` 下可能截在滑入中途，只看到弹层顶栏。判弹层内容对不对就去读 DOM，别信截图。
4. 截图里 toast 正好浮在内容上，虚拟时间跑够 2 秒它自己就消失了。

### 每次改动跑这一串

录入 → 改份数 → 删一条 → 切日期再切回来 → 新建自定义食物并用它记录 → 刷新页面验证持久化 → 核对 kcal 与独立重算一致。

碰食物库和统计时再加两条：

- **改食物**验历史条目跟着变、份数没变、别的食物的条目没被误改、统计页跟着刷新
- **平均口径**用「今天故意录一条超大值」来验：区间终点必须是昨天，均值不能被今天拉高
- **配置隔离**：在一个配置里录数据 → 切到另一个配置，食物库/今日/统计必须都是空的；切回来数据还在（`state` 是指针，容易切漏）
- **拖动排序**：按住最左灰条 → 下移 → 再拖到屏幕顶端（长列表要滚到真正的第一条）→ 松手后 `state.foods` 和 localStorage 里的顺序都要变；`pointerup` 后不能顺手打开编辑面板
- **拖动过程要拖满一整屏**：跨过好几行之后还必须跟手，松手必须落下——只拖一小段测不出丢 capture

## 存量数据与回退 —— 动手改之前看这节

- 数据只在浏览器 localStorage 里，清缓存、换设备、换域名（端口变了也算）都会丢。所以「设置」页必须保留 JSON 导入导出
- 导出现在是**整个 store**（全部配置）；导入要同时认两种：带 `configs` 的完整备份、旧格式的 `{profile,foods,logs}`（只覆盖当前配置）
- 导入拆成两层：`onImportFile` 只负责读文件，真正落数据的是 `applyImport(obj)`。写自动化验证时直接调 `applyImport`，别等 FileReader——headless 的 `--virtual-time-budget` 会把虚拟时间跑在真实 I/O 前面，FileReader 偶发读不完，表现为「导入了但没反应」
- 改 `index.html` 之前先复制一份 `index.html.bak`，出问题整文件换回去，比逐行 revert 快
- 食物库预置数据在 `DEFAULT_FOODS`。「清空当前配置的数据」会重新载入它；**新建配置是空库**，别把预置数据塞给新配置
